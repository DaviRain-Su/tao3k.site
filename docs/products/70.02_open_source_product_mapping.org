* Purpose and scope

This is a source-linked working inventory for the existing Platform, Products and
Solutions navigation. A repository is not automatically a separately packaged
product, a deployment, or an end-to-end integration. Project documentation
owns implementation and release status. The classifications below are a site
presentation proposal, not a replacement for those owners' contracts.

Recipes are project-owned material. Do not introduce a new top-level Recipe
navigation category or assume that every project uses a shared recipe format.

* Solutions: security, healthcare and financial examples

Cedar POO Spec combines LeanPoo composition with the Cedar Lean specification
and checks exported cases with the official Rust authorizer. It owns reusable
security and authorization controls as well as example scenarios; industry
controls and platform integrations are separate. Examples include:

- [[https://github.com/hardenedlinux/cedar-poo-spec/blob/main/CedarPooSpec/Vertical/Health/README.org][Healthcare]]: disclosure, emergency access and FHIR consumer-access controls.
- [[https://github.com/hardenedlinux/cedar-poo-spec/blob/main/CedarPooSpec/Vertical/FinancialServices/README.org][Financial services]]: banking ownership, controller release, insurance and payment-signing controls.
- [[https://github.com/hardenedlinux/cedar-poo-spec/blob/main/Examples/Scenarios/README.org][Security scenarios]]: tenant/device policy migration and source-bound wallet scenarios.

These are reusable models, tests, exports and scenarios, not evidence that a
hospital connector, real signer, production gateway or end-to-end deployment
is available. The consuming Host authenticates facts, enforces decisions and
owns real effects. The repository's [[https://github.com/hardenedlinux/cedar-poo-spec/blob/main/Productions/README.org][production profile documentation]] retains
those boundaries.

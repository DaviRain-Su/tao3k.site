* Presentation direction

[[https://moderne.ai/][Moderne]] presents code search and large-scale code changes around concrete
engineering outcomes. For tao3k, present a broader direction that can connect
source-aware code discovery, domain knowledge, rule-based reasoning, formal
methods and governed agent work. Show each project's individual role and mark
cross-project combinations as a direction until their explicit integration gates
are demonstrated. Avoid implying that every search result is formally verified
or that an LLM can establish a proof without a named checking boundary.

Illustrative user questions:

- Which code owns this behavior, what calls it, and which tests cover it? ASP
  language-provider search is a source-backed starting point.
- Which facts and rules support a conclusion, and what remains unknown? MRR
  separates typed derivation, lineage and admission.
- Which claim became stale after a change? Lambda Aitia models revision-bound
  justification and invalidation for software/SDLC.
- Which domain conditions matter? Lambda Episteme contributes vertical
  Profiles and Cases; an application explicitly selects them.

* Outstanding qualification

- Trace the specific ASP-to-MRR and Scheme/Agent/LLM handoffs to actual current
  integrations and real application receipts before presenting a unified tool.
- Identify the formal search or verification task, input identity, checked
  model or theorem and result boundary for each example. Distinguish finite
  model checking from general theorems and runtime behavior.
- Preserve existing project ownership: Deterministic Engineering organizes
  engineering definitions and methods; Aitia owns its independent causal
  assurance policy. The README's capture-blocked status is not a product win.
